## 1. 이 프로젝트가 뭔가

코딩 에이전트(Claude Code)가 시크릿 평문을 읽지 못하게 막는 **가드레일**이다.
단일 Go 바이너리 `aeg` 로 만들고, Claude Code 의 PreToolUse 훅으로 동작한다.

**시크릿 매니저가 아니다.** 볼트·암호화·주입·출력 마스킹은 전부
[dotenvx](https://dotenvx.com) 가 한다. AgentEnvGuard 는 그 위에 얹혀서
에이전트가 규칙을 지키도록 강제하는 얇은 층이다.

목표는 **우발적 노출 차단**이다. 의도적 탈취는 막지 못하고 막는 척도 하지
않는다 (`d=dotenvx; $d get X` 로 우회된다). 이 한계를 README 에 명시한다.

## 2. 확정된 결정

### 기존 도구 조사 결과

| 도구 | 판정 | 이유 |
|---|---|---|
| `amannirala13/envguard` | **기각** | `run` 계열 명령이 없다. Python 스크립트가 키를 받는 경로가 `envg get`(stdout 평문) 또는 `export --unsafe`(평문 파일)뿐 — 막으려는 실패 모드 그 자체. 마스킹도 자기 출력에만 적용. OS 키체인 저장이라 헤드리스 Linux 에서 깨짐. alpha, 스타 2개 |
| `dotenvx` | **채택** | `run --`, `--redact` 마스킹, 커밋 가능한 ECIES 암호문 `.env`, 헤드리스 동작, 단일 바이너리 배포를 전부 이미 가짐. BSD-3-Clause. 서브프로세스로 호출하므로 라이선스 전파 없음 |

**핵심 사실:** dotenvx 암호문 `.env` 는 **키 이름이 평문, 값만 암호문**이다.
따라서 에이전트가 `.env` 를 그냥 읽어도 안전하고, 어떤 키가 있는지 스스로
파악할 수 있다. 별도의 "값 없는 키 목록" 생성기가 필요 없다.

### 이름

프로젝트 **AgentEnvGuard**, 바이너리 **`aeg`**.

`Agent` 접두어가 차별점(막는 상대가 git 도 사람도 아닌 에이전트)을 담는다.
바이너리를 짧게 분리한 건 CLI 관례(`git`, `jq`, `rg`, `sops`, `direnv`)
때문이다. `aeg` 는 PATH·Homebrew 모두 비어 있음을 확인했다.

### 설계 결정 3건 (Claude Code 훅 문서 조사에서 나옴)

1. **`Grep` 을 훅 매처에 반드시 포함한다.** Grep 은 매칭된 줄 내용을
   반환하므로 `Grep(pattern="DOTENV_PRIVATE_KEY", path=".env.keys")` 한 번이면
   Bash 도 Read 도 거치지 않고 개인키가 나온다. 초안에서 빠져 있던 **실제
   보안 구멍**이었다. 매처는 `"Bash|Read|Grep"`.
2. **차단 출력은 exit 2 + stderr 가 아니라 JSON `permissionDecision`.**
   종료코드를 판정 신호로 쓰면 의도적 차단과 크래시가 구분되지 않아
   fail-open 을 안전하게 구현할 수 없다. `aeg hook` 은 **항상 exit 0**.
3. **훅을 `args: ["hook"]` exec form 으로 등록**해 셸 기동 비용을 없앤다.

### 운영 결정

- **메시지는 한국어로 둔다.** 영어화의 유일한 목적은 공개 배포이고, 지금
  바꾸나 나중에 바꾸나 비용이 같다(24개 문자열). 테스트가 메시지 본문이
  아니라 명령 이름(`aeg init`, `dotenvx run`)만 검사하므로 나중에 바꿔도
  테스트가 안 깨진다. 계획 Task 11 에 항목으로 남아 있다.
- **실행 방식은 서브에이전트 방식**(superpowers:subagent-driven-development).
- **작업 위치는 `feat/aeg-mvp` 브랜치, 같은 디렉터리.** 워크트리를 쓰지
  않는 이유: 새 저장소라 동시 작업이 없어 격리 이익이 없고, Go 빌드·dotenvx
  테스트·Task 11 의 `/usr/local/bin` 설치 검증이 한 곳에서 끝난다.
  **master 는 문서만 담고 그대로 둔다.**

## 4. 계획 요약 (11 태스크)

안쪽 순수 함수부터 바깥으로 쌓는다. 각 태스크는 테스트를 먼저 쓰고 실패를
확인한 뒤 구현하고 커밋한다. **외부 Go 의존성 0, 표준 라이브러리만.**

| # | 태스크 | 산출 |
|---|---|---|
| 1 | 프로젝트 초기화 + `.env` 암호화 판별기 | `go.mod`, `.gitignore`, `internal/policy/envfile.go` |
| 2 | 경로 분류기 | `internal/policy/path.go` |
| 3 | Bash 명령 분류기 | `internal/policy/command.go` |
| 4 | 사용자 예외 목록 (`~/.config/aeg/allow`) | `internal/allowlist/` |
| 5 | 판정 엔진 `Decide()` | `internal/policy/types.go`, `engine.go` |
| 6 | Claude Code 어댑터 | `internal/adapter/` |
| 7 | `aeg hook` + `main.go` + 성능 벤치마크 | 첫 실행 바이너리 |
| 8 | `aeg install` (settings.json 멱등 병합) | `internal/cmd/install.go` |
| 9 | `aeg scan` | `internal/cmd/scan.go` |
| 10 | `aeg init` | `internal/cmd/initcmd.go` |
| 11 | 실제 검증 + README + LICENSE | 실제 Claude Code 세션에서 차단 확인 |

의존 방향: `cmd` → `adapter` → `policy` → `allowlist`. 역방향 없음.

**성능 예산: `aeg hook` 1회 10ms 이내.**

## 7. 함정

- **`.swp` 파일.** 과거에 `git add -A` 로 vim 스왑 파일이 커밋된 적이 있다
  (`3a68206` 에서 제거). Task 1 의 `.gitignore` 가 `*.swp` 를 막는다.
  스펙 문서를 vim 으로 열어둔 채 편집하면 또 생긴다.
- **`git mv` 는 내용 수정을 스테이징하지 않는다.** 인덱스의 기존 blob 을
  옮길 뿐이라 `git commit -m` 만 하면 파일명 변경만 커밋되고 본문 수정이
  빠진다. 실제로 한 번 겪었다. `git commit -a` 를 쓰거나 따로 `git add`.
- **Task 11 이 실질 관문이다.** 단위 테스트가 다 통과해도 실제 Claude Code
  훅으로 안 막히면 의미가 없다. `/usr/local/bin` 설치 후 **새 세션**에서
  `cat .env.keys` 를 시켜봐야 한다. 실패하면
  `cp ~/.claude/settings.json.aeg-backup ~/.claude/settings.json` 으로 되돌린다.
- **`aeg install` 은 사용자의 `~/.claude/settings.json` 을 건드린다.**
  백업(`.aeg-backup`)을 남기게 설계했지만, JSON 재직렬화 때문에 키 순서가
  알파벳순으로 바뀐다. 계획에 적혀 있다.
